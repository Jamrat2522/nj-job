# HR V2 (NJV.30) — คู่มือ Deploy · เวอร์ชันปัจจุบัน: **v2-preview-1**

> ⚠ รอบนี้เป็น **Preview เพื่อทดสอบ Production Integration เท่านั้น**
> ห้าม Cutover · ห้ามประกาศให้พนักงานใช้ · Feature Flag เปิดเฉพาะ SUPER_ADMIN + ผู้ทดสอบ · Write Lock เปิดอยู่
> จะเปลี่ยนชื่อเป็น `v2-full-*` ได้ก็ต่อเมื่อ R1–R8 เสร็จ + ทดสอบ Production จริง + เทียบผลกับ V1 ครบ (ดู DEFERRED.md)

## หลักการ
- V2 อยู่ที่ `/hr-v2/` แยกจาก V1 100% — **ห้ามทับ ห้ามลบไฟล์ V1**
- ไม่มี Service Worker ใน V2 (โดยตั้งใจ) — cache-busting ทำผ่าน `?v=<BUILD>` ทุกไฟล์ JS/CSS อัตโนมัติจาก `index.html` + `ctx.load`
- เวอร์ชันกลางเก็บบนเซิร์ฟเวอร์ (ตาราง `njhr_app_release` ผ่าน SQL 96) — เบราว์เซอร์เทียบทุกครั้งที่: เปิดแอป / refresh / เปลี่ยน route / แท็บกลับมา active / เน็ตกลับมา / ทุก 3 นาที
- เวลาอ้างอิง Maintenance = เวลาเซิร์ฟเวอร์ (`server_time` จาก `njhr_version_status`) ไม่เชื่อนาฬิกาเครื่อง

## ลำดับ Deploy รอบแรก (v2-preview-1)
1. ตรวจว่า SQL `96_version_control.sql` ติดตั้งแล้ว (ทำแล้ว — current_version เริ่มที่ v2-core-0)
2. อัปโหลดโฟลเดอร์ `hr-v2/` ทั้งชุดขึ้นโฮสต์ (ที่เดียวกับ V1 แต่คนละโฟลเดอร์)
3. เปิด `https://<โดเมน>/hr-v2/` → login SUPER_ADMIN → หน้า `#/system`
4. ตรวจ `#/system` ก่อน: โหมดต้องเป็น **PREVIEW** · การบันทึกข้อมูล = **ล็อกอยู่** · SW ของ V2 = ไม่มี
5. กด "ประกาศเวอร์ชันใหม่" ใส่ `v2-preview-1`
   - ไฟล์ที่อัปโหลดคือ v2-preview-1 อยู่แล้ว → ผู้ทดสอบ V2 จะถูกบังคับโหลดชุดใหม่ · ไม่กระทบ V1
   - ยังไม่ต้องติ๊ก Maintenance ในรอบแรก (ยังไม่มีผู้ใช้ค้างในระบบ)
5. รัน PRODUCTION-CHECKLIST.md ให้ครบ

## ลำดับ Deploy รอบถัดไป (ทุกครั้ง — กฎ 47/48)
1. แก้ `window.NJHR_V2_BUILD` ใน `index.html` เป็นเวอร์ชันใหม่ เช่น `v2-preview-2`
2. อัปโหลด **ไฟล์ทั้งชุดของรุ่นใหม่ให้ครบก่อน** (index.html เป็นไฟล์สุดท้าย)
3. เข้า `#/system` → "ประกาศเวอร์ชันใหม่" = `v2-preview-2` (จะเริ่ม Maintenance 10 นาทีอัตโนมัติตามที่ตั้งใน SQL 96)
4. ระบบจัดการเองทั้งหมด: บังคับ logout ทุก session V2 · บล็อก login · นับถอยหลัง · เปิดระบบใหม่ · ทุกเครื่องโหลดไฟล์ `?v=v2-preview-2`
   → รอบ Preview นี้กระทบเฉพาะบัญชีผู้ทดสอบ เพราะพนักงานทั่วไปยังถูกปิดด้วย Feature Flag
- ถ้าอัปโหลดล้มเหลวกลางคัน: **อย่าประกาศเวอร์ชัน** — ผู้ใช้ยังอยู่รุ่นเดิมอย่างสมบูรณ์ (atomic ด้วยลำดับ ไฟล์ก่อน-ประกาศทีหลัง)
- ถ้าประกาศแล้วพบไฟล์ผิด: ประกาศกลับเป็นเวอร์ชันเดิม แล้วแก้ไฟล์ให้ครบก่อนประกาศใหม่

## เกณฑ์เลื่อนขั้นเป็น v2-full-*
ทำครบทุกข้อจึงเปลี่ยนชื่อ BUILD ได้: R1–R8 เสร็จ → ทุก Module ทดสอบกับข้อมูล Production จริง →
เทียบผลกับ V1 ตรงกันทุกรายการ → PRODUCTION-CHECKLIST ผ่านทั้งหมด → คุณอนุมัติ Cutover เป็นลายลักษณ์อักษร

## Rollback
- ปิดการเข้าถึง V2: ตั้ง Feature Flag ปิดทุก role ที่ `#/system` (หรือ `select njhr_version_maintenance('full', 525600, 'ปิดปรับปรุง');`)
- V1 ไม่ได้รับผลกระทบใด ๆ — ไม่มี rollback ฝั่ง V1 เพราะไม่เคยแตะ
- ถอน SQL 96 (กรณีสุดท้ายจริง ๆ): `drop function` njhr_version_* + `drop table njhr_app_release` — ไม่มีตาราง/ฟังก์ชันเดิมถูกแก้ จึงถอนได้สะอาด
