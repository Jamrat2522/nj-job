# ฟอนต์ไทยของ Edge Function njhr-doc-pdf

## ไฟล์ในโฟลเดอร์นี้

```
Prompt-Regular.ttf   168,932 ไบต์   MD5 b863c5f643db4ff31f49b76954579dc9
Prompt-Bold.ttf      178,804 ไบต์   MD5 50006469c4225a1a1e4174f161dd3390
OFL.txt              สัญญาอนุญาต
```

**Prompt** โดย Cadson Demak ภายใต้ **SIL Open Font License 1.1**
ดาวน์โหลดจากคลัง Google Fonts อย่างเป็นทางการ
(`github.com/google/fonts` → `ofl/prompt/`)

OFL 1.1 อนุญาตให้ฝังในเอกสาร แจกจ่ายพร้อมซอฟต์แวร์ และใช้ในเชิงพาณิชย์
โดยต้องแนบสัญญาอนุญาตไปด้วย — ไฟล์ `OFL.txt` จึงอยู่ในโฟลเดอร์นี้

เป็นฟอนต์ตัวเดียวกับที่หน้าเว็บใช้อยู่แล้ว เอกสารกับหน้าจอจึงหน้าตาเป็นชุดเดียวกัน

## การรองรับอักขระ (ตรวจจากไฟล์ฟอนต์จริง)

ทั้ง Regular และ Bold รองรับครบ:
พยัญชนะไทย 46 ตัว · สระ 16 ตัว · วรรณยุกต์ 4 ตัว · เครื่องหมายไทย 6 ตัว ·
เลขไทย 10 ตัว · เลขอารบิก 10 ตัว · อังกฤษพิมพ์ใหญ่และพิมพ์เล็กอย่างละ 26 ตัว

## ⚠ ข้อบกพร่องที่ยังเหลืออยู่ — ความกว้างของวรรณยุกต์

PDF ที่สร้างได้จริงแล้ว ภาษาไทยอ่านออกและคัดลอกได้ครบ
แต่**มีช่องว่างกว้างเท่าตัวอักษรแทรกหลังวรรณยุกต์**

สาเหตุ (ตรวจจากไฟล์ PDF จริง):
`pdf-lib` สร้างตาราง `/W` จาก glyph ที่ map ตรงจากรหัสอักขระเท่านั้น
แต่ฟอนต์ไทยเลือก glyph ตัวแปรตามบริบทผ่าน GSUB
glyph กลุ่มนี้ (เช่น 721 · 723 · 724) ไม่ถูกใส่ใน `/W`
โปรแกรมอ่าน PDF จึงใช้ค่าปริยาย `/DW = 1000`

**ยังไม่พร้อมส่งให้พนักงาน** จนกว่าจะแก้เรื่องนี้
รายละเอียดและทางแก้ที่เป็นไปได้อยู่ในคอมเมนต์หัวข้อเดียวกันใน `wht50.ts`

ตรวจซ้ำได้ด้วย `node harness/wht50_pdf_render_test.js .`
ซึ่งจะสร้าง PDF จริงและรายงาน glyph ที่ขาดออกมาให้เห็น
