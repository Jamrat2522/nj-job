RUN-140 — Root Cause และสิ่งที่แก้
================================================================
Root Cause
  njhr_att_late_min() ใช้ (extract(epoch …)/60)::int ซึ่ง Postgres "ปัดเศษ"
  จุดตัดจริงจึงอยู่ที่ 30 วินาที ไม่ใช่ 1 นาที
      08:30:00.000-08:30:29.999 -> 0 นาที -> ปกติ
      08:30:30.000-08:30:59.999 -> 1 นาที -> มาสาย   <-- ผิด
  ทั้งสองช่วงแสดงบนหน้าจอเป็น "08:30" เท่ากัน จึงเห็น 08:30 เป็นทั้ง ปกติ และ มาสาย
  ไม่เกี่ยวกับ timezone และไม่เกี่ยวกับการ format

ค่าจริงของ record ตัวอย่าง (ก่อนแก้)
  0339 ณัฐวดี ห้วยกรด   16/09  08:30:59.122  -> late_min 1  LATE
  0339 ณัฐวดี ห้วยกรด   01/09  08:30:19.906  -> late_min 0  NORMAL
  0302 สุดารัตน์ ศรีแก่บ้าน 16/09  08:30:56.489  -> late_min 1  LATE  (เคสที่ผู้ใช้ชี้ 08:30-21:51)

สิ่งที่แก้
  1. njhr_att_late_min            ::int -> floor()  (แก้คำเดียว ไม่แตะบรรทัดอื่น)
  2. njhr_att_correction_approve  เลิกใช้สำเนาสูตร ให้เรียก njhr_att_late_min ตัวกลาง
     สำเนาเดิมต่างจากตัวกลาง 3 จุด: ปัดเศษ 30 วิ · หัก late_allow หลังปัดเศษ ·
     ใช้ ::time ลบกันไม่มีวันที่ ทำให้กะข้ามคืนผิด
  3. Backfill attendance.status 41 แถว จาก LATE -> NORMAL (เก็บค่าเดิมไว้ใน
     public.njhr_run140_backfill_log ย้อนกลับได้)

ผู้ใช้ค่าจาก njhr_att_late_min (แก้จุดเดียวได้ผลทุกที่)
  njhr_att_punch · njhr_att_migrate · njhr_att_report · njhr_att_summary

  แถวสถานะขัดกับสูตรใหม่ = 0 ทั้งสองทิศทาง
  41 แถวที่แก้ เวลาเข้าอยู่ในช่วง 30-59 วินาทีหลังเริ่มกะทั้งหมด
  ไม่มีแถวใดกลายเป็น "มาสาย" เพิ่ม (ทิศทางเดียวคือลดลง)

Root Cause
  RC-1  apprWhoState() ไม่มีสถานะ "ขั้นที่ผ่านแล้ว"
        หลัง RUN-128 Backend (njhr_appr_steps_snap) ตัด Future Step ทิ้งก่อนส่งมาแล้ว
        steps ที่ Frontend ได้รับจึงมีได้แค่ "ขั้นปัจจุบัน" กับ "ขั้นที่ผ่านแล้ว"
        แต่โค้ดยังตกไปที่ป้าย "ยังไม่ถึงขั้น" ทุกกรณีที่ไม่ใช่ขั้นปัจจุบัน
        หลักฐาน Production: 260902-0007 (cur=3 · steps 3 ขั้น) และ 260902-0002 (cur=2 · steps 2 ขั้น)
        แต่ละใบมีผู้อนุมัติในขั้นที่ผ่านแล้ว 1 คนที่ไม่ได้กด → ถูกแปะว่า "ยังไม่ถึงขั้น"
  RC-2  apprStepsHTML() คำนวณ wait เองโดยไม่เช็ค status
          var wait = cur && s.step_no === cur;        (ขาด && status === "PENDING")
        Production มี CANCELLED 6 แถวที่ current_step ยังค้าง 1–2
        (APPROVED / REJECTED เป็น NULL หมดแล้ว) → ใบที่จบแล้วกลับไปโชว์ "รออนุมัติ"
  RC-3  apprStepsHTML() ไม่รู้จัก step_mode = ANY
        หน้าอนุมัติกับหน้าพนักงานจึงเขียนข้อความคนละอย่างกับใบเดียวกัน
  RC-4  apStepsHTML() (ฝั่งพนักงาน) ขั้น ALL ที่ผ่านแล้ว / ใบที่ปิดแล้ว
        ตกไปที่ "รอดำเนินการ" ซึ่งยังสื่อว่าค้างอยู่

                              และ flow ขึ้นต้นด้วย ATTENDANCE เท่านั้น
  ~ perfEnd()                 Freeze Snapshot "ก่อน" PERF.t = null
                              perfPush() historical ยังทำงานตามเดิมทุกบรรทัด
  ~ perfCurrentRun()          ลำดับ Face Data: Active PERF.t > Completed Snapshot ของ run เดียวกัน

                              ห้ามถอยไปใช้ lastAny('ATTENDANCE') หรือ Historical Log เด็ดขาด
  ~ perfRunScopedReset()      + PERF.completed = null  (ใช้ทั้ง Run Reset และ clear())
  ~ Export step0_metrics      + face_source: ACTIVE_FLOW | COMPLETED_SNAPSHOT | NOT_OBSERVED
