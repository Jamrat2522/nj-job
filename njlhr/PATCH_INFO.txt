Root Cause
  perfEnd() ตั้ง PERF.t = null เมื่อ Face Flow จบ
  แต่ perfCurrentRun() อ่าน Face Metrics จาก PERF.t อย่างเดียว
  → Lifecycle จริง perfStart() → สแกนหน้า → perfEnd() → Export
    ทำให้ button_to_result_ms / descriptor_p50_ms / descriptor_count ฯลฯ
    ของ Run ปัจจุบันหายเป็น null/0 ทันที

สิ่งที่แก้ (face.js)
  + perfCloneFlat(o)          คัดลอกค่าออกเป็น Object ใหม่ (Snapshot ไม่อ้าง reference เดิม)
  + PERF.completed            Snapshot ของ Face Flow ที่จบแล้วใน Run ปัจจุบัน
                              เก็บ run_id · run_type · flow · platform · ms · count · completed_at
                              ⚠ ไม่มีรูปใบหน้า ไม่มี Descriptor จริง
  + perfCompletedForRun()     คืน Snapshot เฉพาะเมื่อ run_id ตรงกับ Run ปัจจุบัน
                              และ flow ขึ้นต้นด้วย ATTENDANCE เท่านั้น
  ~ perfEnd()                 Freeze Snapshot "ก่อน" PERF.t = null
                              perfPush() historical ยังทำงานตามเดิมทุกบรรทัด
  ~ perfCurrentRun()          ลำดับ Face Data: Active PERF.t > Completed Snapshot ของ run เดียวกัน
                              > ไม่มี = null / 0 / NOT_OBSERVED
                              ห้ามถอยไปใช้ lastAny('ATTENDANCE') หรือ Historical Log เด็ดขาด
  ~ perfRunScopedReset()      + PERF.completed = null  (ใช้ทั้ง Run Reset และ clear())
  ~ Export step0_metrics      + face_source: ACTIVE_FLOW | COMPLETED_SNAPSHOT | NOT_OBSERVED
                              + face_completed_at

Completed Snapshot เก็บที่ไหน / ผูก run_id อย่างไร
  เก็บที่ PERF.completed (memory เท่านั้น ไม่ persist)

  ตอนอ่านต้องตรงกับ run_id ปัจจุบัน ไม่ตรง = ไม่ใช้

Run Reset / clear()
